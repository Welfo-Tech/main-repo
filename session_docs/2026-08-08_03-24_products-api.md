## Endpoints

### ProductModels — `/api/v1/product-models`

| Method | Path | Role               |
|--------|------|--------------------|
| GET    | /    | any                |
| GET    | /:id | any                |
| POST   | /    | ADMIN, OPERATIONS  |
| PATCH  | /:id | ADMIN, OPERATIONS  |
| DELETE | /:id | ADMIN only         |

DELETE sets `isActive: false` — ProductModel has no `deletedAt`, deactivation is the equivalent.

### Products — `/api/v1/products`

| Method | Path | Role               |
|--------|------|--------------------|
| GET    | /    | any                |
| GET    | /:id | any                |
| POST   | /    | ADMIN, OPERATIONS  |
| PATCH  | /:id | ADMIN, OPERATIONS  |

No DELETE endpoint — products are never removed; they move through ProductStatus (REGISTERED → IN_SERVICE → UNDER_REPAIR → RETIRED → SCRAPPED etc.) via PATCH.

## Key decisions

**Products include nested relations on every response:**
`productSelect` includes `model { id, name, category, manufacturer }` and `ownerOrg { id, name }` so callers never need a second request to display the product.

**Serial number conflict handling without Prisma namespace import:**
`@repo/db` does not export the `Prisma` namespace. Duck-typed the P2002 check: `"code" in err && err.code === "P2002"` → throws `ConflictError`. This avoids adding a new export to the db package.

**ProductModel deactivation not soft-delete:**
ProductModel schema has no `deletedAt`. DELETE route calls `deactivateProductModel` which sets `isActive: false`. This preserves catalog history while hiding inactive models from default list views (filter `isActive: true`).

**Date fields use `z.coerce.date()`:**
Zod automatically coerces ISO date strings (`"2024-01-15"`) to `Date` objects. This keeps the schema simple and works with Prisma's `@db.Date` fields.

**No status-change endpoint:**
Status is updated via PATCH. If business rules around valid state transitions become important (e.g. RETIRED cannot go back to IN_SERVICE), a dedicated `POST /products/:id/status` endpoint should be added with transition validation. That belongs in the ServiceCase domain work.
