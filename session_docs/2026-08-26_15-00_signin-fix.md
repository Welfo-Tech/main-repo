## Session: fix sign-in — everything blocking login resolved

Date: 2026-08-26

Commit: 20bd29f

### Root causes (all fixed)

**1. Wrong DB adapter — Neon WebSocket vs standard TCP**

`packages/db/src/client.ts` was using `@prisma/adapter-neon` (WebSocket-based). Prisma 7 requires an explicit adapter. The Neon WebSocket adapter is designed for serverless edge runtimes — in a Node.js container it emits WebSocket error events outside the async/await chain, causing `app.fetch` to reject silently (returning text/plain 500 with no log entry).

Fixed by switching to `@prisma/adapter-pg` (standard TCP PostgreSQL), which:
- Works identically with local PostgreSQL and Neon's direct URL
- Produces properly serializable errors (caught by the error handler and logged)
- Removes the `ws` and `@neondatabase/serverless` dependencies entirely

**2. No local PostgreSQL for Docker**

The API Docker container couldn't reach the Neon database (ETIMEDOUT — Docker NAT doesn't route to Neon). Added a `postgres:16-alpine` service to docker-compose so the stack is fully self-contained.

**3. DATABASE_URL mismatch between host and container**

From the host machine, `localhost:5432` reaches postgres (port-mapped). From inside the API container, it needs `postgres:5432` (Docker network hostname). Fixed by hardcoding the container-network URL in docker-compose for the api and services services.

**4. NEXT_PUBLIC_API_URL not set at build time**

`NEXT_PUBLIC_*` vars in Next.js are baked in at build time. The admin Dockerfile had no build ARG for it, and there was no `.env` file in `apps/admin/`. Result: every fetch in the browser went to `undefined/api/v1/auth/login`.

Fixed by:
- Adding `ARG NEXT_PUBLIC_API_URL=http://localhost:4000` to the admin Dockerfile
- Passing it as a docker-compose build arg
- Adding `process.env.NEXT_PUBLIC_API_URL ?? "http://localhost:4000"` fallback in login page
- Adding `apps/admin/.env.example` for local dev instructions

**5. No CORS headers**

Browser blocked all API responses because there was no `Access-Control-Allow-Origin` header. Added Hono's built-in `cors()` middleware to `apps/api/src/app.ts` — echoes the request origin, allows standard methods and the Authorization header, credentials enabled.

**6. Error handler crashing silently**

When the error wasn't serializable (original Neon WebSocket error), `logger.error({ err })` threw because pino tried to JSON-serialize a non-serializable error. The `onError` function itself threw, causing `@hono/node-server` to return a bare 500 text/plain with no body. Fixed with a `safeLog` wrapper and try/catch around the entire error handler.

### Additional fixes during this session

**Prisma config — seed command**

Prisma 7 moved the seed command from `package.json` to `prisma.config.ts`. Added `migrations: { seed: 'tsx ./prisma/seed.ts' }` to `packages/db/prisma.config.ts`.

**Seed — `dotenv/config` missing**

`packages/db/prisma/seed.ts` imported `prisma` from `src/client.ts`, which reads `DATABASE_URL`. But the seed process had no dotenv loaded, so `DATABASE_URL` was undefined and `PrismaPg` threw a SASL error. Added `import "dotenv/config"` as the first line of `seed.ts`.

**Seed — wrong enum values**

`COLONOSCOPE` is not a valid `ProductCategory` (valid: `ENDOSCOPE`). `DIAGNOSIS` is not a valid `ServiceCaseStatus` (valid: `UNDER_ASSESSMENT`). Both fixed.

**Prisma generated client out of sync**

The generated client had `outstandingAmount` on Invoice (from an older schema design), but the current schema.prisma doesn't have it, so the actual database column doesn't exist. The upsert tried to SELECT this column and failed. Fixed by running `prisma generate` to regenerate the client from the current schema.

### Dev workflow for database (after this session)

- **Migrations and seed for Neon (CLI tools):** use `packages/db/.env` — has the real Neon URL
- **Migrations and seed for local postgres (Docker dev):** run with `DATABASE_URL=postgresql://welfo:welfo@localhost:5432/welfo`
- **API in Docker:** connects to `postgres:5432` (container network) — hardcoded in docker-compose
- **Login credentials:** `admin@welfo.local` / `welfo@admin123`
